# 发件箱与定时发送

iMail 的定时发送由 Rust 服务执行，不依赖浏览器或前端计时器。写信界面提交任务时，会把邮件正文、收件人、回复关联头和附件保存为不可变快照；后续修改原草稿不会静默改变已安排的内容。

## 用户流程

1. 在写信界面选择“定时”，使用快捷时间或当前设备时区下的自定义时间。
2. 任务进入“发件箱”，计划时间统一以 UTC 持久化，界面按当前设备时区展示。
3. 进入 SMTP 发送阶段前，可以取消任务并让关联草稿重新出现在草稿箱。
4. 明确失败的任务可以人工重试。重试会更新计划时间并再次入队，不会自动无限重试。
5. 服务在发送过程中中断或 SMTP 结果无法确认时，任务进入“待人工核对”，不会盲目重发。用户必须先检查服务商的“已发送”文件夹，再选择“已在已发送中找到”或“确认未发送，返回草稿”。

“取消待发送”不等于撤回。邮件一旦进入发送阶段，iMail 不再提供取消操作；SMTP 服务已接收的邮件也无法由本功能撤回。

## 状态模型

| 状态 | 含义 | 可用操作 |
| --- | --- | --- |
| `scheduled` | 已持久化，等待计划时间 | 取消并返回草稿 |
| `sending` | 已领取发送租约，正在提交 SMTP | 无 |
| `sent` | SMTP 返回成功，或用户核对后标记已发送 | 无 |
| `failed` | 发送前出现明确的本地或领域错误 | 重试；取消并返回草稿 |
| `needsReview` | 发送结果不确定，禁止自动重放 | 人工核对为已发送；确认未发送后返回草稿 |
| `cancelled` | 发送前已取消，或人工确认未发送 | 草稿可继续编辑 |

后台领取任务时使用数据库事务和十分钟发送租约。同一任务只有一次领取能从 `scheduled` 进入 `sending`。如果服务在租约期间中断，租约到期后任务转为 `needsReview`，而不是再次发送。

## 控制面

应用 HTTP 和 MCP 使用同一份 SQLite 状态机与所有权检查：

| 应用 HTTP | MCP 工具 | 用途 |
| --- | --- | --- |
| `GET /api/outbox` | `outbox_list` | 列出任务摘要和状态，不返回正文或附件 Base64 |
| `POST /api/outbox` | `outbox_schedule` | 保存不可变快照并安排发送 |
| `DELETE /api/outbox/:id` | `outbox_cancel` | 取消尚未发送的任务 |
| `POST /api/outbox/:id/retry` | `outbox_retry` | 仅重试明确失败任务 |
| `POST /api/outbox/:id/resolve` | `outbox_resolve` | 人工处置不确定结果 |

`outbox_schedule` 使用 `accountEmail` 选择发件账户，并要求 RFC 3339 格式的 `sendAt`；应用 HTTP 使用账户 ID。服务只接受当前时间附近至未来一年内的计划时间。MCP 的修改类工具只对 `mcp:full` 授权码开放，并写入管理工具审计事件。

## 运行边界

- 桌面嵌入式服务和独立 HTTP 服务都会启动同一调度器；服务离线时不会发送，到期任务会在服务恢复后继续处理。
- 发件箱数据库升级为 schema 15。迁移只新增 `outbox_items`，不会改写既有邮件和草稿内容。
- 列表模型不暴露正文、附件内容、邮箱凭据、OAuth Token 或加密字段。
- 任务成功后，关联草稿被删除；任务处于活动、失败或待核对状态时，关联草稿从普通草稿列表隐藏，但仍保留在本地数据库中。

## 验证范围

- SQLite 测试覆盖安排、原子领取、完成、明确失败、过期租约转人工核对、两种人工处置及 v14 到 v15 迁移。
- MCP 集成测试覆盖工具发现、安排、列出和取消。
- Playwright 覆盖写信、定时浮窗尺寸、任务进入发件箱及发送前取消。
- 提交门禁继续包含前端类型检查、单元测试、生产构建、Rust 格式化与 Clippy。
