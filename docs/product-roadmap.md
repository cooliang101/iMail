# iMail 功能扩展路线图

更新日期：2026-08-31

评估基线：`697502b`

状态：“写信能力补齐”“会话视图”“高级搜索与智能文件夹（含正文全文检索）”已实现；搜索验证与范围见[高级搜索与智能文件夹](advanced-search.md)。其余项目仍为候选，阶段顺序不代表版本或交付时间承诺。功能完成不等于已发布安装包。

## 目标与现状

iMail 已具备多邮箱接入、后台同步、搜索、标签、草稿、富文本写信、附件预览、联系人、翻译、Apple Hide My Email、HTTP Gateway 和 MCP 等基础能力。后续扩展重点是提高接入后的日常处理效率，而不是继续扩大邮箱服务商数量。

本路线图围绕三条主线：写信完整度、邮件整理与检索、受控自动化。现有 Windows 代码签名、更新渠道等公开发行准备仍属于交付工作，不在本文重复展开。

## 第一阶段：补齐写信能力

已实现并完成本地验收，行为与验证覆盖见[写信与会话](composition-and-conversations.md)。

### 范围

- 回复全部：处理原发件人、收件人和抄送人，排除自己的邮箱身份并去重。
- 密送 Bcc：贯穿草稿保存、恢复、发送协议和相关控制面，不只新增前端输入框。
- 账户签名：按发件账户配置，新邮件与回复可分别控制插入行为。
- 模板与快捷短语：保存常用内容并在写信时插入，允许插入后继续编辑。
- 附件遗漏提醒：正文提到附件但未添加时提醒，允许用户确认后继续发送。

### 关键边界

- 回复目标需要评估 `Reply-To`，不能始终只采用 `From`；多发件身份的自地址排除策略需在实施时明确。
- Bcc 地址只供有权访问草稿及发送任务的当前用户使用，不应通过投递给收件人的公开邮件头或日志泄露。
- 切换发件账户或恢复草稿时，不重复插入签名，不覆盖用户已编辑的正文。
- 模板和签名按用户隔离；HTML 继续遵守现有安全处理规则。

### 验收重点

- 混合 To/Cc、重复地址、自己的地址、Reply-To 的回复全部结果正确。
- Bcc 草稿关闭重开不丢失；协议测试同时检查 SMTP 收件人和投递 MIME 中的隐私边界。
- 签名和模板插入不破坏富文本、附件与自动保存。
- Tauri 本地和 HTTP 远程模式保持行为一致，相关 HTTP/MCP 能力同步评估。

## 第二阶段：保存搜索与基础规则

### 保存搜索和智能文件夹

已实现，规则引擎仍为候选。

- 将已有搜索扩展为可组合的账户、发件人、收件人、日期、已读、星标、附件和标签条件。
- 支持保存、重命名、删除查询，并将其显示为动态视图。
- 智能文件夹只保存条件，不复制或移动邮件；用户只能查询自己拥有的数据。
- 普通关键词覆盖主题、摘要和参与者；正文使用独立条件与本地 FTS5 索引，详见第三阶段。
- “等待对方回复”等需要往来关系判断的视图，待会话关系能力就绪后再纳入，不以主题关键词替代。

### 规则引擎

先实现确定性条件和有限动作，不以 AI 分类作为基础依赖。

| 条件示例 | 动作示例 |
| --- | --- |
| 发件人为指定 GitHub 通知地址 | 添加“开发通知”标签并静音 |
| 主题包含“发票” | 添加“财务”标签 |
| 发件人属于指定客户域名 | 添加“客户”标签并保留通知 |

规则必须提供历史邮件匹配预览、启用开关、优先级和执行记录。预览不产生远程邮箱副作用；对历史邮件执行规则必须单独确认。

### 关键边界与验收

- 规则在持有数据的 iMail 服务实例执行，不依赖页面是否打开，也不宣称创建了服务商侧规则。
- 第一版不自动永久删除邮件，也不自动转发邮件。
- 需要明确“继续匹配/停止匹配”、动作冲突、重复同步和失败重试语义，避免重复执行。
- 涉及远程归档的动作使用现有邮件领域服务，不能只改变本地显示。
- 搜索结果、分页与数量统计一致；增量同步后智能文件夹内容正确更新。
- 验证多用户隔离、规则预览与实际执行一致性，以及重启恢复和安全裁剪后的错误记录。

## 第三阶段：会话视图与正文全文检索

### 会话视图

已实现并完成本地验收；以下范围不包含正文全文检索。

- 评估通过 `Message-ID`、`In-Reply-To` 和 `References` 建立往来关系。
- 支持在同一阅读视图展开多封邮件、折叠引用和查看往来历史。
- 不能仅凭主题相同合并会话；缺失或异常邮件头需要明确兜底。
- 同一封邮件在多个文件夹或账户中的副本，不应因聚合而失去其真实所属位置和操作目标。
- 会话级已读、归档等批量动作在实施时单独设计，不能把视觉聚合直接等同于批量写操作。

### 正文全文检索

已实现：FTS5 trigram、短词扫描、历史回填与事务增量维护；准确匹配语义和合成基准见[功能文档](advanced-search.md)。下列验收边界继续适用。

- 在现有搜索基础上增加正文条件，使用 SQLite FTS5 本地索引。
- 中英文及混合文本按字面子串匹配，按邮件时间排序，不做词语分词或相关性排序。
- 支持历史邮件索引补建、增量更新、删除同步和索引重建。
- 显示本地缓存与已索引内容的搜索范围，不承诺搜索从未同步到本实例的正文。
- 附件内容全文检索不属于第一版正文搜索范围。

### 验收重点

- 回复头缺失、循环引用、重复 Message-ID、相同主题不同往来的场景不会错误串联。
- 检索结果与用户及账户权限一致，清除邮箱数据时索引同步清除。
- 在大邮件量、长正文和中英文查询下测量检索延迟、索引大小和重建耗时。
- 查询/索引变更通过迁移和备份恢复测试，桌面与 Docker 共用实现。

## 第四阶段：发件箱与受控 Agent 自动化

### 持久化发件箱

- 保存延迟发送和定时发送任务，展示计划时间、状态及最近错误。
- 允许取消尚未提交给 SMTP 的任务；“取消待发送”不是撤回已经投递的邮件。
- 邮件发送不能依赖前端计时器，应由 Rust 服务执行并持久化状态。
- 本地桌面退出或远程实例停机期间不能发送，需要向用户说明任务依赖对应服务在线。
- 实施时确定时区、休眠恢复、逾期任务处理和发送内容快照策略。

可靠性重点是避免重复发送：SMTP 已接受邮件但本地尚未记录成功时可能出现不确定结果，不能承诺端到端严格一次发送，也不能盲目自动重试。需要区分明确失败、明确成功与结果待核对，并设计人工处理入口。

### Agent 自动化

优先复用现有 MCP，不以新增完整聊天界面为前置条件：

- 总结指定范围内的重要邮件。
- 提取待办事项、日期和待回复对象。
- 根据邮件生成回复草稿，保留用户最终编辑和发送入口。
- 对批量整理生成操作预览，经确认后执行。

### 安全边界与验收

- AI 默认输出草稿和建议；发送、删除及大范围修改需要明确审批策略。
- 邮件正文、HTML、附件及其中的指令均是不可信内容，不得改变工具授权或诱导自动外发。
- 使用第三方模型前明确告知将外发的数据范围，允许用户选择不启用；避免无关邮件被一并发送。
- 候选只读邮件授权不改变现有账户管理边界：账户管理仍必须使用 `mcp:full`。
- 若引入审批，应绑定准确的邮件、收件人、正文和动作集合；审批后内容变化需重新确认。
- 覆盖发送过程崩溃、并发领取、重启恢复、Token 撤销、审批过期和恶意邮件指令等测试。

## 后续候选

### 附件工作区

先基于附件元数据提供跨邮箱列表、类型/日期筛选和来源定位，再增加受限批量下载。继续复用现有按用户隔离的附件缓存，不另建永久附件库；下载使用并发和体积限制，不自动拉取全部历史附件。

### 订阅邮件管理

先做发件人聚合与批量整理，再评估标准退订邮件头。退订可能产生外部请求或发送邮件，必须展示目标并由用户确认；不能把正文中的任意“退订”链接直接作为可信自动操作入口。

## 暂不优先扩展的范围

- 原生移动端及原生 Linux/macOS 桌面发行。
- 团队共享邮箱、工单分配和组织级权限系统。
- 本地与远程独立实例之间的双向自动数据同步。
- 任意脚本插件或可执行任意 CSS 的主题系统。

这些方向会扩大平台、授权或数据一致性边界，需要单独确认产品需求与架构，不作为本路线图的默认任务。

## 实施与维护约束

- 本文用于记录产品方向，不自动授权实现、真实邮箱操作或发布；每次执行以用户明确选择的范围为准。
- 各阶段启动前明确最小范围、数据模型、迁移方案与可验证的完成条件，不一次性展开所有候选功能。
- 前端按领域归属 feature，复用统一表单控件，保持 `App.tsx` 只负责编排；设置继续遵循两级导航及单项原地展开规则。
- 领域行为在 Rust 服务实现，HTTP/MCP/Gateway 共用 `crates/imail-http/`；本地/远程适配器不得维护不同业务语义。
- 新增邮件或账户行为时同步评估 HTTP API、MCP 工具、契约测试和 [MCP 指南](mcp-integration.md)，保持现有调用兼容性。
- 自动化测试使用隔离数据与协议 fixture；真实邮箱发送、移动和 Apple HME canary 只在显式授权下运行。
- 验证按风险覆盖单元、契约、迁移、浏览器 E2E 和必要的 Windows/Docker smoke；提交前执行仓库规定的前端三项检查。
- 本路线图不包含前端首屏 CSS 预算优化；该项按当前约定暂缓。
- 实施完成后把准确行为写入对应功能或架构文档，再更新本文状态；失效或已完成的规划通过 Git 历史保留，不长期堆叠快照。
