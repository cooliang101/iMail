# 高级搜索与智能文件夹

更新日期：2026-08-31。高级搜索在 0.1.12 后加入，随 0.1.13 内部测试包交付；数据库 schema 为 13，不代表正式公开发行。

0.1.14 统一高级搜索入口与工具栏图标样式；搜索弹窗固定标题和底部操作区，仅表单主体滚动，并使用主题化细滚动条。账户和标签展开后不再产生嵌套滚动。

## 使用与范围

搜索栏旁的“高级”打开组合查询；左侧“智能文件夹”可以新建、打开、编辑名称和条件或确认删除保存的查询。删除仅移除查询定义，不复制、移动或删除邮件。保存失败会保留表单，允许重试。

从普通邮件视图进入时保留当前账户、工作空间、文件夹、标签及参与者范围；可在面板中清除范围限制。选择“所有文件夹”的高级查询不隐含收件箱限制。搜索结果沿用时间倒序及稳定游标分页，总数表示完整条件下的匹配量，不是游标后的剩余量。同步完成后重新查询服务端，正文匹配不依赖前端摘要缓存。

| 条件 | 语义 |
| --- | --- |
| 账户 | 所选账户任意一个；空列表表示当前用户全部账户 |
| 关键词、主题、正文 | 各字段分别做字面包含查询；关键词覆盖主题、摘要、发件人和 To/Cc，不包含正文 |
| 发件人、收件人 | 完整邮箱地址匹配；收件人覆盖 To 和 Cc，不搜索 Bcc |
| 日期 | 按邮件时间查询，开始包含、结束不包含；界面使用设备时区，接口使用 RFC 3339 时间戳 |
| 已读、星标、附件、稍后处理 | 不限/是/否三态；`false` 不等于省略条件 |
| 标签 | 同时具有全部所选标签 |
| 文件夹、工作空间 | 与其他条件取交集 |

所有不同条件取交集。保存的文件夹按 iMail 用户隔离，每用户最多 100 个，名称最多 80 个 UTF-16 单元；单次条件最多 100 个账户、30 个标签。删除账户不会自动扩大已保存的账户范围；再次编辑保存时须移除已不存在的账户条件。多端修改以单个文件夹为单位提交，更新同一个文件夹采用后写覆盖，不覆盖其他文件夹。

## 正文索引

仅搜索本实例已缓存的 `messages.text_body`，不请求远程邮箱搜索，不索引附件。HTML 邮件是否可搜索取决于同步解析后存储的纯文本正文。索引随数据库存放，包含正文派生内容，应按邮件数据库同等级保护。

采用 SQLite FTS5 trigram：三个及以上 Unicode 字符使用索引候选集，再校验字面子串；一至两个字符直接扫描正文，数据量大时更慢。ASCII 字母大小写不敏感，其他字符按字面匹配；不提供中文词语分词、词干化、相关性排序或搜索表达式。引号、`%`、`_`、`OR` 等不作为用户可执行的 SQL/FTS 语法。

schema 13 迁移会为历史正文回填索引；后续正文插入、更新和删除由同一数据库事务中的触发器维护。首次升级耗时与缓存量有关，应预留磁盘空间并先备份；不要用旧版本直接打开升级后的数据库。数据库备份包含智能文件夹和索引，恢复继续使用现有备份/恢复流程。

管理员需要重建时，先停止使用目标数据目录的服务并备份，设置 `IMAIL_DATA_DIR` 为准确目录，再执行：

```powershell
cargo run --release --locked -p imail-storage-sqlite --bin imail-maintenance -- search-rebuild
```

该命令针对整个实例，不是用户级操作；没有对应的 HTTP、MCP 或 Gateway 全局重建接口。

## HTTP、桌面与 MCP

HTTP `GET /api/messages` 的可选 `filters` 参数为 URL 编码后的 JSON 对象，契约见 `contracts/search-filters.json`；与旧参数同时提供时取交集，未提供时保持旧查询行为。示例对象：

```json
{"body":"季度预算","recipient":"finance@example.com","unread":false,"labels":["财务"]}
```

登录会话保护的智能文件夹接口：

| 方法与路径 | 请求/响应 |
| --- | --- |
| `GET /api/smart-folders` | `{ "folders": [...] }` |
| `POST /api/smart-folders` | 请求 `{ "name": "预算", "filters": {...} }`，响应 `{ "folder": {...} }` |
| `PUT /api/smart-folders/:id` | 完整替换名称与条件，响应 `{ "folder": {...} }` |
| `DELETE /api/smart-folders/:id` | `{ "deleted": true }` |

无效条件返回 400，不存在或不属于当前用户的文件夹返回 404。请求不能指定所有者。桌面通过类型化调用进入同一领域实现，不维护第二套存储语义。

MCP `messages_list` 接受同一 `filters` 对象；新增 `smart_folders_list`、`smart_folder_save`、`smart_folder_delete`。读取文件夹定义后，将其 `filters` 传给 `messages_list` 执行查询。所有工具仍要求 `mcp:full`，不增加凭据输出。

Gateway 邮件列表也接受 JSON `filters`，但始终与 Token 授权账户、用户和指定邮箱/隐私地址范围取交集，条件不能扩大权限。智能文件夹管理不加入 Gateway。

## 验证记录与限制

隔离数据覆盖条件组合、To/Cc、否定布尔值、时区、用户与 Token 账户隔离、游标总数、历史迁移、索引增删改/重建和保存后重新打开数据库。真实 Rust 服务的浏览器验收覆盖保存、刷新恢复、重命名、70 条结果跨页去重、同步后新增匹配、失败重试、删除不删邮件及桌面/窄屏布局。

本机 Windows debug 合成基准：10,000 封邮件，每封基础正文约 4,800 UTF-8 字节；插入并索引约 1.90 秒，重建约 1.59 秒，FTS data 表负载约 36.7 MB（不是完整数据库或完整索引文件大小）。一次中文常见词查询约 284 毫秒，英文/混合唯一词约 3 毫秒，双字扫描约 334 毫秒。结果受硬件、缓存、正文分布和并发影响，不代表生产 SLA。

规则引擎、附件全文搜索、跨实例同步与“等待对方回复”等关系推断视图不在本次范围。
