# 附件预览

iMail 支持在邮件阅读界面按需查看 JPEG、PNG、GIF、WebP、BMP、PDF、MP4、WebM、Ogg 视频、纯文本文档和 ZIP 压缩包。DOCX、PPTX、DOC、PPT、SVG、加密 ZIP 与嵌套压缩包当前只允许下载。

纯文本文档包括 TXT、Markdown、CSV、TSV、JSON、XML、YAML、日志、INI、CONF、CFG、TOML、Properties 和 SQL。Rust 层支持 UTF-8、带 BOM 的 UTF-16 LE/BE 和 GBK，并在交给前端前统一转换成 UTF-8；单个文本预览最大 5 MB。Markdown 作为纯文本安全展示，不解析其中的 HTML，也不加载外部资源。

## 处理边界

- `imail-mail` 从邮箱服务器读取原始附件；完整原文 FETCH 使用标准括号 fetch-items，并依次兼容 `BODY.PEEK[]`、`RFC822` 与 `BODY[]`。UID 失效时先请求服务器按 Message-ID 重新定位；若 iCloud 等服务器未返回搜索结果，Rust 会分批读取实际存在邮件的最小 Message-ID 头部并在本地匹配。邮件被服务器移动但本地文件夹尚未同步时，还会按归档、全部邮件、已发送和其他可选文件夹的优先级跨文件夹定位；定位过程不会下载无关邮件的正文或附件。
- 首次读取成功后，下载、预览、Gateway 和 MCP 共用按应用用户隔离的本地附件缓存；附件字节不进入邮件 SQLite 缓存和授权导出。
- `imail-attachment` 根据文件头识别类型，执行图片尺寸、附件大小、ZIP 路径和解压膨胀限制。
- `imail-http` 创建与当前用户绑定的短期预览会话，并为视频提供 HTTP Range 响应。
- Tauri 本地模式通过类型化领域调用创建会话，通过二进制 IPC 读取内容，不开放本地业务 HTTP 端口。
- 前端只展示服务确认的资源类型；ZIP 在 Rust 中按单项解压，前端不会接收整个压缩包进行解压。

原始附件磁盘缓存使用内容摘要校验，单项最大 50 MB，按用户最多保留 512 MB，三十天后过期；“清除我的邮箱数据”会同步删除当前用户的附件缓存。预览会话二十分钟后过期，关闭查看器时客户端会主动释放。单用户预览会话内存上限为 100 MB，全局上限为 256 MB。

## ZIP 限制

- 最多 1,000 个条目；
- 单项最大解压大小 50 MB；
- 总解压声明大小最大 200 MB；
- 超过 1 MB 的条目最大压缩比为 100:1；
- 拒绝绝对路径、父目录、Windows 盘符语义和符号链接；
- 不自动解压到磁盘，不执行内部文件。

ZIP 内受支持的图片、PDF、视频和纯文本文档可以按需查看。其他条目只展示名称与大小，不提供应用内打开。
