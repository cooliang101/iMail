# 邮件规则引擎

入口：设置 → 邮件规则。桌面本地模式与服务端模式复用 Rust 引擎和 SQLite 持久化模型，数据库版本为 14。规则在持有邮箱数据的 iMail 实例运行，不创建服务商侧规则；退出桌面进程或停止服务后不会继续执行。

## 条件与动作

每条规则包含名称、启用开关、优先级、账户范围、全部/任一条件、动作和“匹配后停止”。账户范围留空表示当前用户的全部账户，包括未来添加的账户。

| 条件 | 语义 |
| --- | --- |
| 发件人、收件人 | 完整地址，不区分 ASCII 大小写；收件人包含 To/Cc |
| 发件人域名 | 完整域名，不隐式包含子域名 |
| 主题包含、正文包含 | 不区分大小写的字面子串，不支持正则或 SQL 通配符；正文只使用本实例缓存 |
| 附件、未读、星标 | 布尔条件 |
| 文件夹类型、标签 | 匹配保存的文件夹角色或标签 |

动作支持添加/移除标签、静音/恢复通知、标记已读/未读、添加/取消星标、归档。标签与静音是本地状态；已读、星标和归档通过现有远程邮件领域服务提交到邮箱服务器。归档必须是该规则的最后一个动作。不提供自动删除、转发或任意脚本。

上限：每用户 100 条规则，每条 1–20 个条件、1–20 个动作、最多 100 个指定账户；名称 1–80 字符，优先级 0–10000。

## 自动执行与去重

- 完成首次收件箱同步之后，新发现的收件才参与自动匹配。首次导入、已有缓存、其他文件夹的历史扫描不会自动批量执行规则。
- 数字较小的优先级先执行；相同时按创建时间和 ID 排序。所有规则匹配同一份原始邮件快照，前一条新增的标签不会成为后一条的匹配条件。匹配到“停止匹配”规则后，不再选择后续规则。
- 标签或静音冲突由后执行的匹配规则覆盖。本地动作与远程待执行记录在同一事务提交。远程动作依次执行；同一邮件较早的未完成记录阻止后续远程动作，其他邮件不受影响。
- 去重键是用户、规则 ID、修订版、账户和邮件标识。有 RFC Message-ID 时使用它，否则退回本地 ID。同一账户里相同 RFC Message-ID 的副本视为同一封邮件；没有该头时无法保证跨 UID 重建去重。
- 保存规则增加修订版；修改、停用和删除取消旧版本尚未开始的任务。已经发出的远程命令可能完成，但不会继续剩余动作，也不会撤销已完成的操作。中断后的旧版本任务不会被重新启动。
- 静音抑制该邮件的新邮件通知，并从通知中心候选中排除；不改变未读状态。

## 历史邮件预览与确认

1. 编辑时可只读预览；先保存规则才能执行历史邮件。
2. 预览显示匹配总数、可执行数量和最多 50 封样本；样本数不是执行上限。范围是本实例缓存，不会为预览访问远程邮箱。
3. 点击处理历史邮件后仍需单独确认。HTTP/MCP 必须提供 `confirmed: true`。
4. 执行使用预览绑定的完整候选集合，不在确认时重新搜索。令牌绑定用户、规则修订版和邮件指纹，有效期 10 分钟、仅可使用一次。同一用户新预览替换旧预览。规则或候选邮件变化会拒绝整个请求，需要重新预览。

历史执行只运行所选的一条规则，不运行整个优先级链。已停用但已保存的规则也可显式手动执行。已经执行过当前修订版的邮件会从可执行数量中排除。仅有标签/静音的规则不会触发网络同步；涉及远程动作时才加入持久化同步队列。

## 故障与恢复

远程动作逐步保存进度，不重复提交已确认完成的动作。已读和星标设置最多自动尝试 3 次，失败重试间隔至少 1 分钟；账户授权失败和同步退避遵守现有策略。执行中租约为 10 分钟，重启后可恢复安全的状态设置动作。

归档失败、进程中断或缺少明确目标 UID 时记为“需要核对”，不伪造本地移动，也不自动重放。请先检查远程邮箱，此状态不提供盲目重试。“执行失败”可显式重试当前版本的未完成动作。修改或删除规则不会消除不确定归档的核对记录。

设置展示最近 200 条记录：规则名、账户、来源、完成动作数、状态、时间和安全错误码。内部去重记录不随展示截断而删除。错误不保存供应商原始响应、密码或 Token。删除账户级联删除对应记录；清除用户邮件数据同时清除规则及预览。备份恢复包含这些 SQLite 数据，升级前应备份，勿用旧程序直接打开已迁移数据库。

## HTTP、桌面与 MCP

HTTP 使用当前用户会话，桌面本地桥接调用相同实现。账户、规则、预览和记录均按用户隔离。MCP 仅允许 `mcp:full`，不加入普通 HTTP Gateway。

| HTTP | MCP 工具 |
| --- | --- |
| `GET /api/mail-rules` | `mail_rules_list` |
| `POST /api/mail-rules`、`PUT /api/mail-rules/:id` | `mail_rule_save` |
| `DELETE /api/mail-rules/:id` | `mail_rule_delete` |
| `POST /api/mail-rules/preview` | `mail_rule_preview` |
| `POST /api/mail-rules/apply` | `mail_rule_apply` |
| `GET /api/mail-rule-runs` | `mail_rule_runs` |
| `POST /api/mail-rule-runs/:id/retry` | `mail_rule_retry` |

规则输入示例（MCP 保存时放在 `input` 中；更新另提供 `ruleId`）：

```json
{
  "name": "开发通知",
  "enabled": true,
  "priority": 100,
  "accountIds": [],
  "matchMode": "all",
  "conditions": [{ "field": "senderDomain", "value": "github.com" }],
  "actions": [
    { "type": "addLabel", "value": "开发通知" },
    { "type": "mute", "value": true }
  ],
  "stopProcessing": false
}
```

请求结构以 `contracts/mcp-tools.json` 和 `crates/imail-http/src/rules.rs` 为准。

存储测试覆盖匹配、优先级、停止、隔离、预览与一次性确认、修订失效、初次同步跳过、去重、静音、动作冲突、恢复、有限重试及执行中修改/删除。运行时用合成 IMAP 适配器验证领域服务调用、确认后的 UID 持久化及最终增量事件，不连接真实邮箱。HTTP 和前端服务测试覆盖权限及两种客户端路由。
