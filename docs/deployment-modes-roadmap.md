# 本地守护服务与远程共享部署更新路线

## 目标

iMail 桌面应用提供本地服务和远程服务两种可切换的服务模式。两种模式使用同一套服务端能力和 API 协议，区别只在服务实例运行的位置与管理方式。

- 本地服务模式用于开箱即用的单设备场景。服务程序随桌面安装包发布，由桌面应用自动注册和管理为当前操作系统用户的守护进程，不要求用户另行下载安装，也不申请系统级服务权限。
- 远程服务模式用于多设备数据共享。桌面应用不使用本机服务，直接连接用户部署的 iMail 服务；远程服务同时提供浏览器可访问的 Web 客户端。
- 本地与远程是两个独立数据源。切换模式不会自动复制、合并或迁移数据，也不会在连接失败时静默回退。

## 当前基线

Windows 桌面安装包现已装配 Tauri、React 静态资源和独立服务运行程序。桌面客户端可管理回环守护服务或保存远程地址；远程服务以 Docker 镜像交付，并同时提供 API、同步 Worker 与 Web 客户端。

目标不是重写邮件服务，而是在保持现有 API 和安全边界的前提下补齐三项交付能力：

1. 将现有服务构建为可随桌面应用发布的用户级守护程序。
2. 让桌面应用根据所选模式完成守护程序的注册、启动、暂停、升级和移除。
3. 让远程服务发布包同时托管与服务端版本匹配的 Web 客户端。

- “隐私与数据”可使用独立密码导出当前用户全部邮箱的连接配置和授权凭据；导出文件排除邮件、附件、草稿、联系人和 iMail 登录密码，只能由登录会话 HTTP UI 创建和单次下载，不通过 Gateway 或 MCP。邮箱管理同时提供每邮箱级“代理设置”，非密码代理字段从 schema v5 起持久化，代理密码仍进入加密凭据载荷。
- 认证限流和安全审计已持久化到 SQLite：服务重启不重置尝试次数；登录、注册、HTTP 敏感管理动作与 MCP 管理工具调用按应用用户留痕。事件只保存实例盐 HMAC 后的来源、资源 ID 和非敏感动作元数据，保留 90 天且全实例最多 10,000 条；用户只能查询自己的事件。
- Windows 安装版 UI 实机验收发现并修复了 GUI 进程兼任 supervisor 时的 `WebView2Loader.dll` 故障；旧版登录启动参数也会转交给独立管理程序。登录与服务设置已改为互斥视图并隐藏原生页面滚动条；服务设置保留 Tauri 具体错误，端口冲突时允许选择其他非特权端口继续启动。
- 服务程序升级使用暂存副本逐块校验、同目录原子切换和回滚副本；启动失败会恢复旧程序与旧配置，切换中断留下的状态会在下一次启用时先行恢复。
- 客户端模式切换已收敛为可测试事务：目标身份验证、旧服务暂停和配置提交按顺序执行；配置提交、目标检查或生命周期命令部分失败时恢复原本地/远程运行状态，并在恢复也失败时同时保留两段诊断。暂停命令只有在 API 与 supervisor 都已确认退出后才报告成功。
- 远程传输边界已收紧：非回环地址只允许 HTTPS，旧版保存的明文地址会在首个身份或会话请求之前拒绝。前端事务层与 Rust 网络桥双重校验，桌面 HTTP 客户端不跟随重定向，防止 HTTPS 请求体被 307/308 降级转发。
- 远程生产 CORS/Origin 边界不再自动信任本机 Vite 来源：同源部署不需要 CORS，拆分域名只接受显式的纯 HTTPS Origin；生产同主机明文 Origin 也会被 WebSocket 边界拒绝。

## 目标拓扑

```text
本地服务模式

Desktop WebView ── Tauri 网络桥 ──► 用户级 iMail 守护进程 ──► 本机持久数据
                                                   └────────► IMAP / SMTP

远程服务模式

Desktop WebView ── Tauri 网络桥 ──┐
                                  ├─► 远程 iMail 服务 ──► 远程持久数据
Browser ── HTTPS / 同源请求 ──────┘             └──────► IMAP / SMTP
```

桌面 WebView 始终加载安装包内的前端资源。只有浏览器访问远程服务时，前端资源才由远程服务返回。

## 服务模式与设置

设置中心的“服务连接”使用显式二选一，不再用是否填写服务地址推断运行模式。

### 本地服务

- 用户选择本地服务后，桌面应用自动注册并启动当前用户的 iMail 守护进程。
- Windows 使用不要求管理员权限的当前用户后台启动机制；不提供原生 Linux 或 macOS 桌面守护适配。
- 守护进程在用户登录后自动启动，即使桌面窗口未打开也继续执行 IMAP IDLE、周期同步和持久化任务。
- 桌面应用启动时只检查守护进程身份、版本和健康状态；未就绪时显示启动或修复状态，不提前发起登录和邮件请求。
- 关闭窗口、退出桌面 UI 或桌面 UI 崩溃都不停止守护进程。
- 用户显式暂停本地服务、切换到远程模式或卸载本地服务时，桌面应用才请求守护进程优雅停止。
- 数据和主密钥保存在平台用户数据目录，不放入安装目录，也不随桌面 UI 或守护进程停止而删除。
- 守护进程只监听回环地址，不因启用本地模式扩大到局域网。

### 远程服务

- 桌面应用连接用户填写并验证的服务地址；远程地址必须使用 HTTPS，HTTP 仅允许本机回环开发地址。
- 所有 API、SSE、附件、Gateway 和 MCP 展示地址从选定的远程服务地址派生。
- 远程服务不可达时保持远程模式并显示连接错误，不自动切换到本地服务。
- 多台桌面应用和浏览器直接访问同一远程实例，从而共享账户、邮件缓存、草稿和服务端设置；客户端之间不另建同步协议。
- 切换到远程模式时默认暂停本机守护进程，避免两个实例同时维护相同邮箱的独立缓存。保留本机数据和注册信息，方便以后切回。

### 模式切换

- 从本地切到远程：先测试远程地址并确认兼容，再暂停本机守护进程，最后切换客户端数据源。
- 从远程切到本地：启动并验证本机守护进程后切换客户端数据源；远程地址继续保留。
- 两种模式分别保留会话状态，切换后必须针对目标服务重新检查登录状态。桌面网络桥按规范化服务地址持久化且隔离 Cookie Jar，因此返回此前使用过的服务时可以恢复尚未过期的 30 天会话，同时不会把会话令牌交给前端。
- 任一步骤失败都保持原模式，避免停在没有可用服务的中间状态。
- 切换只改变当前数据源。迁移本地数据到远程实例属于未来独立能力，不包含在本路线中。

## 守护进程与故障边界

本地守护进程是独立的用户级后台进程，不是桌面 UI 的子进程，也不是拥有系统权限的系统服务。

- 桌面应用负责注册、启用、暂停、升级和移除守护进程；操作结果必须可查询、可重试、可诊断。
- 服务启动必须带有实例身份与健康检查，不能仅凭端口已监听就认定目标是 iMail。
- 桌面应用只能管理自己注册且身份匹配的守护进程，不能按端口或进程名结束未知进程。
- 守护进程异常退出时由平台用户级守护机制按有限退避策略恢复；持续失败时退避上限为 30 秒，并保留失败次数、退出码和时间等安全诊断状态。
- 服务日志写入用户日志目录并执行轮转；错误界面只显示安全摘要，不暴露邮箱凭据、OAuth Token 或加密字段。
- 本地服务默认监听 `127.0.0.1:8787`；端口冲突时可在桌面服务设置中选择其他 `1024–65535` 端口，选定端口会同步保存到客户端与用户级守护配置。实例 UUID 与协议握手继续用于区分受管实例，桌面不会连接或终止未知服务。

## 安装、升级与卸载语义

“选择本地服务”本身就是一键启用流程，不出现要求用户下载另一安装包的引导。

- 桌面安装包携带 Windows 服务程序和默认配置模板。
- 首次启用时将服务程序部署到稳定的用户级运行目录，注册用户级守护项，然后启动并等待健康检查。
- 桌面升级时先验证新旧协议与迁移条件，再安全替换守护程序；不能直接覆盖运行中的文件。
- 守护程序、桌面前端和数据库迁移按同一桌面版本测试和签名。
- “暂停本地服务”只停止同步和 API，不删除注册信息或数据。
- “移除本地服务”注销守护项并删除运行文件，默认保留数据。
- 暂停或移除会记录为独立于服务模式的用户意图；应用重启和登录检查不得自动撤销该状态。用户再次选择“本地服务”时才清除暂停标记并重新部署或启动守护程序。
- 卸载桌面应用默认只移除程序并保留数据；“服务连接”也不提供删除入口。清除当前用户邮箱数据属于登录后的“隐私与数据”动作，必须经过范围复核、当前密码与固定确认文字，并且不停止或移除守护程序。

## 构建与发布单元

### 桌面安装包

包含：

- Tauri 桌面壳与平台能力；
- React 前端生产资源；
- 与桌面版本匹配的 iMail 服务程序及必要运行资源；
- 用户级守护进程的注册、状态查询、启动、停止、升级与移除能力。

桌面安装包不预创建用户数据，不把数据库写入安装目录，也不注册系统级服务。

### 远程服务发布包

包含：

- API、同步 Worker、Gateway 与 MCP；
- 数据库迁移；
- React Web 生产资源；
- 健康检查和版本信息端点。

远程生产部署优先提供容器镜像，并要求外部持久卷保存数据库、发件人 Logo、日志和加密主密钥。首期仍按单实例 SQLite 部署，不声明水平扩容能力。

### Web 静态资源

- `/` 和前端路由返回 Web 应用外壳。
- `/api`、`/gateway` 与 `/mcp` 保持现有协议，不进入 SPA fallback。
- 带内容哈希的资源使用长期缓存，`index.html` 使用短缓存或不缓存。
- 浏览器默认使用当前页面的同源服务地址；桌面运行时使用服务模式产生的地址。
- Service Worker 不缓存 API、MCP、Gateway、SSE 或其他用户数据响应。

## 版本兼容

远程服务可能与桌面应用独立升级，本地守护程序则随桌面版本发布，因此需要明确兼容契约：

- 服务提供不含敏感信息的实例身份、服务版本、API 协议版本和能力列表。
- 桌面应用在切换服务及启动时先完成兼容性检查，再进入登录流程。
- 协议不兼容时阻止业务请求并给出升级方向，不能以未知字段或随机失败代替版本错误。
- 本地守护程序、桌面前端和数据库迁移作为同一桌面版本验证；升级失败时不得使用新客户端强行打开未完成迁移的数据。
- Web 客户端与远程服务在同一发布单元中构建，默认保持版本一致。

## 远程生产边界

远程模式的目标是用户自托管的多设备共享实例，不等同于公开 SaaS。进入公开网络前至少需要：

- HTTPS、反向代理安全头和可信代理配置；
- 明确的初始化与注册策略，避免部署后长期开放任意注册；
- 持久化限流、登录与管理操作审计；
- 数据、主密钥和 Logo 文件的备份恢复流程；
- 正确的 OAuth 回调基地址、Web 前端地址和 MCP Host/Origin allowlist；
- SSE 与 WebSocket 的反向代理超时配置；
- 升级前备份、数据库迁移和失败回滚说明。

## 分阶段实施

### 阶段 0：冻结运行契约（已完成）

- 定义 `local` / `remote` 服务模式及其本地持久化结构。
- 定义守护程序的实例身份、健康检查、就绪、优雅关闭和退出码。
- 通过 Windows 用户级后台机制验证安装、启动、崩溃恢复与注销。
- 决定端口分配与冲突处理方式。
- 定义客户端与服务端版本兼容响应。
- 调整原有“桌面包不得包含服务端”的架构测试，使其验证新的进程和安全边界。

完成标准：生命周期、平台注册、端口、数据目录、版本检查和故障提示都有可测试契约。

### 阶段 1：服务模式设置（已完成）

- 将服务模式与远程服务地址拆成独立配置。
- 设置页提供本地/远程二选一和对应状态。
- 远程模式保留地址测试；本地模式展示注册、启动、运行、暂停、异常和日志入口。
- 切换模式时重新检查目标服务会话，不自动搬迁数据或静默回退。

完成标准：现有独立服务仍可作为远程模式使用，且界面不再用是否填写地址推断模式。

### 阶段 2：Windows 用户级守护程序（构建已验证，登录重启待实机验收）

- 将现有 Node 服务构建成 Windows 桌面可携带的服务程序。
- 在 Tauri 中实现用户级注册、身份验证、健康检查、暂停、升级和移除。
- 将数据、密钥和日志定位到平台用户数据目录。
- 覆盖重复启用、端口冲突、守护程序崩溃、桌面退出、系统登录和升级迁移测试。

完成标准：全新设备选择本地服务后无需另装程序即可使用；桌面 UI 退出后守护程序继续同步，用户暂停或移除后不再运行。

### 阶段 3：远程服务托管 Web 客户端（已完成并通过容器门禁）

- 在生产服务中托管 Web 构建产物和 SPA fallback。
- Web 默认同源访问 API，并保持桌面内置前端的服务地址解析不变。
- 校验 Service Worker、OAuth 回调、Cookie、CORS、SSE 和附件下载。
- 产出包含 Web 资源的远程服务容器镜像。

完成标准：部署一个远程发布单元后，桌面客户端可连接，浏览器也可直接访问同一地址。

### 阶段 4A：内部测试交付（当前阶段）

- 补齐远程初始化、注册控制、审计、备份恢复、schema v5 账户代理持久化，以及用户级数据清除和加密授权导出。
- 建立 Windows 与 Docker 构建矩阵；Windows 生成内部 NSIS，Docker 验证远程 Web、API、Worker、健康检查与持久卷。
- 执行本地/远程模式切换、升级、回滚和多设备共享的端到端验证。
- Windows 日常在本机构建、校验并交付，明确授权时可单独运行 `windows` 云任务获取短期 Artifact；`docker` 云任务或版本标签构建 `linux/amd64` 并推送到 GHCR。`0.0.1` 的桌面 Pre-release 只保留为历史证据。
- 更新内测手册、运维手册、README 和故障排查说明。

完成标准：两种模式均有可重复构建、安装、升级、恢复和诊断流程；受控测试人员可以取得与验证平台匹配的安装包。

## 明确不做

- 不要求用户单独下载或手工安装本地服务。
- 不把本地守护程序注册为系统级高权限服务。
- 不实现本地实例与远程实例的双向同步。
- 不在远程连接失败时自动切换数据源。
- 不在模式切换时自动合并账户、草稿或邮件缓存。
- 不为部署模式改变现有 HTTP、Gateway 或 MCP 业务协议。

## 全路线验收场景

1. 全新安装后选择本地服务，桌面应用自动注册并启动用户级守护程序，然后进入初始化流程；默认端口被未知程序占用时，可改选其他回环端口继续，且不会连接或终止占用程序。
2. 退出桌面 UI 后守护程序继续同步；重新打开 UI 后连接同一实例。
3. 系统重启并登录当前用户后，不打开桌面 UI 也能继续收取新邮件。
4. 守护程序崩溃后按受控策略恢复，持续失败时可在桌面设置中查看安全诊断。
5. 切换到远程服务后，本地守护程序暂停，客户端显示远程实例的数据。
6. 远程服务断网时客户端明确报错，不展示本机实例数据。
7. 另一台设备和浏览器连接同一远程实例后看到同一服务端数据。
8. 从远程切回本地后恢复本机实例的数据和登录上下文，不发生隐式合并。
9. 移除本地服务后守护项和运行文件消失，但用户数据默认保留。
10. 桌面或守护程序升级失败时可以诊断和回滚，不损坏既有数据库。
11. “服务连接”没有数据删除入口；“隐私与数据”只有在两阶段确认和当前密码验证都通过后，才清除当前用户的邮箱数据，并保留登录账号、服务与另一用户的数据。
12. 授权导出只能由登录 UI 创建，使用独立密码加密且不含邮件；每邮箱代理在服务重启和 schema v4→v5 升级后仍保持一致。
